# 运行与恢复

生产启动前构建 `go build -o atlas ./cmd/atlas`。通过ATLAS_STATE指定独立可写状态路径，通过ATLAS_ADDR指定受信环境的监听地址。状态目录应由运行进程拥有；临时写文件与最终文件位于同一个目录。

同一状态路径的第二个进程会因为独占文件锁拒绝启动。锁文件可长期存在，锁的有效性由操作系统进程锁决定。不要通过删除锁文件启动第二个写进程。

SIGTERM或中断信号会停止领取任务，取消执行中的计算，等待HTTP请求和执行循环结束。执行中的任务保留running，下一次启动会重新入队。SIGKILL恢复用 `python3 scripts/walkthrough.py --workflow recover-render` 演练；只会结束该脚本自己启动的实例。

备份时先正常停止实例，复制状态JSON；恢复时向空的独立状态路径复制，再启动。不要把运行中手工编辑过的JSON直接作为新事实。启动校验拒绝不支持版本、损坏摘要、孤立关联和非法文档。备份包含PNG字节与全部快照引用闭包，无需从外部素材服务恢复。

容量观察入口是GET /v1/status。它报告未压缩的持久结果PNG字节总量和各任务状态数量，不代表堆内存峰值。完整状态在事务中复制并编码，因此长期积累会增加提交成本。当前未提供任务或快照删除；部署应按预期数据量规划状态盘和实例周期。结果清理入口仅删除PNG字节。历史事件超过500条会截断，但sequence继续增加。

故障时保留当前状态文件和服务日志，在副本上检查。500表示事务未能完成。响应头 `X-Atlas-Commitment` 说明它是否已成为持久事实：`not-committed` 时可用同一幂等键重试；`committed` 时用同一键重放以取得已创建的任务；`unknown` 时先 `GET /idempotency/{key}`，404才表示从未接收。不要因连接中断换用新键。409应结合当前场景revision、快照state或收据语义判断。410说明成功结果字节已清理，任务成功事实仍保留。

写入在原子替换前失败时，持久文件仍是旧版本，内存也保持旧版本；这不影响同一时间其他请求。替换后结果无法确认时，服务会与持久文件核对：若新内容已在文件中则报告 committed，若仍是旧内容则报告 not-committed；只有文件不可读或校验失败才报告 unknown，并要求重启读取。未知原因导致的写入异常不会被报告为可安全重试。

`deploy/atlas.service` 是Linux systemd配置示例，需按实际用户、二进制和状态路径调整。macOS可直接运行同一二进制。当前未验证容器部署、跨进程共享写入、跨机器文件系统锁或网络存储。
